# PAPPL 1.4.12 runtime and lifecycle facts for macOS

Research date: 2026-08-27. PAPPL facts below are pinned to the upstream `v1.4.12` tag (`6db8e137557ad84662e78d24fdb2a591c621f4ac`, released 2026-08-20). The HP Printer Application is cited separately as one upstream PAPPL application’s packaging choice, not as PAPPL-required behavior.

## PAPPL facts

### Process and service model

- `papplMainloop` exposes a long-running `server` subcommand. It constructs and loads the system, then calls the blocking `papplSystemRun`; that run loop exits on a Shutdown-System request, `SIGTERM`, or an API shutdown request. PAPPL installs `SIGTERM`, `SIGINT`, and `SIGHUP` handlers and performs a final save when configuration changed. It does not contain a macOS service installer or a process-user switch in this path. ([main-loop server](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L568-L802), [run loop and signals](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system.c#L394-L495), [final save](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system.c#L837-L859))
- The convenience CLI can auto-start a missing private server with `posix_spawn`, but that process is per-user/private and is not a persistent boot service. For a system service, an external supervisor is expected. ([auto-start path](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-support.c#L430-L511))
- On macOS, launching a PAPPL executable from an `.app` bundle makes the main loop select `server` with `log-file=syslog` and `log-level=info`; in a graphical login session PAPPL can also show its status UI. This is separate from headless system-daemon operation. ([macOS bundle dispatch](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop.c#L122-L152), [graphical-session path](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L772-L802))
- Apple’s `launchd` contract fits PAPPL’s foreground server: a managed process must not daemonize, should handle `SIGTERM`, and should have its user/group configured in the launchd property list rather than changing identity itself. A globally installed daemon must be root-owned. ([Apple: Creating Launch Daemons and Agents](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html))

### Configuration, state, spool, socket, and log locations

For an application whose executable basename is `BASENAME`, PAPPL’s stock main-loop defaults are:

| Artifact | Root/system server on default macOS build | Per-user server | Configurable? |
|---|---|---|---|
| Server configuration | If `HOME` is set, `$HOME/Library/Application Support/BASENAME.conf`; then `/Library/Application Support/BASENAME.conf` | `~/Library/Application Support/BASENAME.conf`; then `/Library/Application Support/BASENAME.conf` | Options in the files or `-o`; a custom system callback can replace stock behavior. |
| Persistent system/printer/job state | `/private/var/lib/BASENAME.state` | `~/Library/Application Support/BASENAME.state` | Not via a stock `state-file` option; customize by registering the application’s own save callback/path before the stock main loop does. |
| Print spool | `/private/var/spool/BASENAME/` | `~/Library/Application Support/BASENAME.d/` | Yes: `spool-directory`. |
| Local control socket | `/private/var/run/BASENAME.sock` | `$TMPDIR/BASENAME<uid>.sock` | Compile-time `--with-papplsockdir` for the root default, or custom listener/main-loop code. |
| Log | A temporary `pappl<pid>.log` if unspecified | Same | Yes: `log-file` accepts a filename, `-` (stderr), or `syslog`; `log-level` is configurable. |

Sources: [config/state selection](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L605-L764), [spool selection and options](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L1623-L1788), [Darwin compile-time state/socket roots](https://github.com/michaelrsweet/pappl/blob/v1.4.12/configure.ac#L635-L661), [socket naming](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-support.c#L596-L636), [log semantics](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system.c#L122-L147), [temporary log fallback](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system.c#L214-L249).

The state file is not merely preferences: it contains system identity/settings, queue definitions, driver and device URIs, printer defaults and state, and job history. Active jobs also depend on document and IPP-attribute files in the spool; if an active job’s document is missing at reload it becomes aborted. ([state format and queue load](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-loadsave.c#L27-L170), [active-job reload](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-loadsave.c#L309-L390))

### Listening, ports, and discovery

- The stock system always adds a Unix-domain socket. Unless `private-server` is set, it also adds TCP listeners. With no `listen-hostname`, `papplSystemAddListeners` binds wildcard IPv4 and IPv6 addresses; a numeric/name value restricts resolution/binding. Therefore a stock non-private server is network-facing, not loopback-only. ([stock listener setup](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L682-L691), [TCP/private decision](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L1772-L1786), [listener semantics](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-accessors.c#L37-L75))
- `server-port` fixes the TCP port. With the default `0`, PAPPL tries the first available port starting at `8000 + (uid % 1000)`, through port 10000; for a root daemon the search begins at 8000. ([automatic port selection](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-accessors.c#L147-L174))
- PAPPL gives the system and queues DNS-SD names by default. On macOS/mDNSResponder it advertises on all interfaces unless the advertised hostname is `localhost`, which makes registration local-only. Printers advertise `_ipp._tcp` and, unless `no-tls`, `_ipps._tcp`, plus an HTTP service; the stock main loop supplies `_print` and `_universal` subtypes. Raw JetDirect listeners/discovery are optional (`raw-socket`) and start at port 9100; they are not enabled by the stock option set. ([DNS-SD interface selection](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/dnssd.c#L389-L398), [IPP/IPPS advertisements](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/dnssd.c#L562-L630), [raw and HTTP advertisement](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/dnssd.c#L634-L690), [stock options](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L1623-L1697))

### Process privilege, authorization groups, and USB

- PAPPL 1.4.12 has no stock `run-as-user`/`run-as-group` server option and the main-loop path does not call `setuid`/`setgid`. `admin-group` and the default print group are request-authorization controls used with PAM; they do **not** choose the process identity. ([server option parsing](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/mainloop-subcommands.c#L1623-L1710), [admin/print group semantics](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-accessors.c#L1543-L1584))
- USB printing exists only when PAPPL is built with libusb. PAPPL enumerates USB printer-class interfaces, opens the device, selects configuration, claims the interface, and performs bulk/control transfers. Kernel-driver detachment is Linux-only in this implementation. PAPPL does not provision a macOS USB driver, entitlement, device ACL, or permission prompt; whether the selected launchd identity can open and exclusively claim the HP USB interface must be verified on supported macOS versions and hardware. ([USB build dependency](https://github.com/michaelrsweet/pappl/blob/v1.4.12/README.md#L33-L53), [conditional USB scheme](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/device-usb.c#L55-L81), [open/claim sequence](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/device-usb.c#L391-L458))
- `PAPPL_SOPTIONS_USB_PRINTER` is unrelated to talking *to* a USB printer: it exposes the default PAPPL queue as an IPP-over-USB gadget and is documented as embedded-Linux-only. Ordinary HP LaserJet USB output uses the `usb:` device scheme/libusb path. ([system option definition](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system.c#L102-L130))

### Upgrade and removal consequences

- Keeping the same executable basename and persistent paths lets the stock main loop reload existing queues and jobs. If a saved driver name is no longer accepted, PAPPL drops that printer and all its job history unless the application’s driver callback maps the old name to a compatible driver. Thus driver-name stability/migration is an application upgrade responsibility. ([state compatibility behavior](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-loadsave.c#L27-L40), [unsupported-driver handling](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system-loadsave.c#L126-L153))
- `papplSystemDelete` closes runtime resources and frees objects but does not remove the state file, spool directory, log, configuration file, or installed service. PAPPL performs ordinary job-history/document cleanup while running (100 completed jobs per printer by default), but product uninstall cleanup is outside the framework. ([system deletion](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/system.c#L280-L323), [default history limit](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/printer.c#L360-L381), [job cleanup](https://github.com/michaelrsweet/pappl/blob/v1.4.12/pappl/job.c#L985-L1025))

## Upstream macOS packaging example (not a PAPPL requirement)

Michael Sweet’s HP Printer Application packages a plist in `/Library/LaunchDaemons`, runs `hp-printer-app server` at load, writes an explicit log under `/Library/Logs`, and therefore runs as root because the plist has no `UserName`. Its package postinstall loads the service. Its build signs the executable, submits it to Apple’s notary service, and signs the installer package. ([plist](https://github.com/michaelrsweet/hp-printer-app/blob/b521969bd1ee558aacf952dfabc35dd10769e093/org.msweet.hp-printer-app.plist#L5-L16), [install/postinstall](https://github.com/michaelrsweet/hp-printer-app/blob/b521969bd1ee558aacf952dfabc35dd10769e093/Makefile.in#L97-L120), [sign/notarize/package](https://github.com/michaelrsweet/hp-printer-app/blob/b521969bd1ee558aacf952dfabc35dd10769e093/Makefile.in#L137-L160), [postinstall](https://github.com/michaelrsweet/hp-printer-app/blob/b521969bd1ee558aacf952dfabc35dd10769e093/macos-scripts/postinstall#L1-L7))

This demonstrates a viable precedent, not the only architecture. Apple says downloaded apps and installer packages are checked by Gatekeeper for an identified-developer signature, notarization, and integrity, while modern macOS also supports app-bundled LaunchDaemons registered through Service Management with explicit user authorization. ([Apple Platform Security: Gatekeeper](https://support.apple.com/guide/security/gatekeeper-and-runtime-protection-sec5599b66df/web), [Apple: updating helper executables](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos))

## Decisions still open for this project

PAPPL does not decide any of the following:

1. Whether the product is a system-wide LaunchDaemon, a per-user agent/app, or manually launched; and whether a modern app-bundled Service Management flow or a conventional signed `.pkg` is used.
2. Which process identity owns USB access. If non-root is preferred, the project must prove that identity can open/claim the HP LaserJet interface and can read/write every persistent path; if root is used, the attack surface and writable inputs need deliberate restriction.
3. Whether IPP/web service is LAN-visible or loopback-only, whether DNS-SD is advertised beyond the host, whether the port is fixed, and whether TLS/authentication/web configuration are enabled.
4. Stable product basename and explicit locations/ownership/modes for configuration, state, spool, logs, socket, and any TLS credentials. Relying on PAPPL’s temporary log or fallback paths is unsuitable for a managed installation.
5. Upgrade behavior: stop/start ordering, preservation and backup of state/spool, driver-name migrations, rollback compatibility, and what happens to active jobs during replacement.
6. Removal behavior: disable/unregister and stop the service first; remove package-owned binaries/plists; separately choose whether user-created queues, job history/spool, configuration, logs, and credentials are preserved by default or purged through an explicit action. PAPPL supplies no uninstaller and does not make that policy choice.
